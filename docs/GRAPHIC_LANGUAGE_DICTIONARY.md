# Graphic Language Dictionary

## Purpose

This document defines projectable Graphic language entries.

It does not define a new shell.
It does not define a new world.
It does not define implementation details.

Its purpose is to answer:

`What concrete Graphic concepts can the creator experience inside Create World?`

This document follows the same semantic discipline that made UIUX projectable:

- Identity
- Meaning
- Evolution
- Next Meaningful Steps
- Capability Domains

The Graphic language model defines the grammar.
This dictionary defines the entries the product can project.

## Governing Rule

Graphic creators should think in:

`Composition`

not:

`canvas objects`

Every entry in this dictionary should reinforce that rule.

## 15. Dictionary Rule

Every Graphic dictionary entry should answer:

- What is this?
- What does it mean inside the composition?
- What can it become?
- What should the creator naturally do next?
- Which capability domains are now relevant?

If an entry cannot answer those questions, it is not yet ready to become a creator-facing language concept.

## 16. Projection Implication

This dictionary gives Graphic enough semantic material to support future:

- graphic empty-world copy
- graphic starter cards
- graphic semantic projection panels
- graphic momentum guidance
- graphic capability projection

That means Graphic is no longer only architecturally placeable.
It is beginning to become experientially projectable.
