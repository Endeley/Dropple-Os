# Create World Creative Initiation Environment Plan

## Purpose

This document defines how the `Creative Initiation` environment should express
its frozen place identity.

It does not redefine what `Creative Initiation` is.

That truth is already frozen in:

- [CREATE_WORLD_CREATIVE_INITIATION_ENVIRONMENT_TRUTH.md](/Users/endeleykonboye/Desktop/dropple-os/dropple/docs/CREATE_WORLD_CREATIVE_INITIATION_ENVIRONMENT_TRUTH.md:1)
- [CREATE_WORLD_CREATIVE_INITIATION_ENVIRONMENT_REVIEW.md](/Users/endeleykonboye/Desktop/dropple-os/dropple/docs/CREATE_WORLD_CREATIVE_INITIATION_ENVIRONMENT_REVIEW.md:1)

This plan exists to answer a different question:

`How should the environment faithfully express the identity of Creative Initiation?`

## Frozen Place Identity

`Creative Initiation is the place where intention becomes direction before creation begins.`

Everything in this plan must support that sentence.

## Planning Question

How should the environment of `Creative Initiation` make that identity
immediately legible to the creator before any creative language, starting
method, or authoring behavior takes over?

## Planning Rule

This plan may express frozen place truth.

It may not invent new truth about:

- what `Creative Initiation` is
- which route must own it
- which shell must host it
- which components must render it
- how CI-1, CI-2, CI-3, or CI-4 are implemented

Those belong to later work.

## Environment Responsibility

The environment of `Creative Initiation` must do five things well:

1. make the identity of the place immediately understandable
2. keep intention as the dominant subject
3. prevent later chapter signals from overwhelming the place
4. preserve continuity with the one Living World
5. prepare a lawful threshold into `Creative Arrival`

## 1. Dominant Attention

The environment should make one thing dominant:

`the beginning of creation`

That means the creator's attention should first land on:

- the purpose of the place
- the opening question
- the sense of direction becoming possible

The creator's attention should not first land on:

- editor controls
- workspace identity
- language-specific shell chrome
- tool affordances
- project-management structure

The environment succeeds when the creator immediately understands:

`This is the place where I figure out how to begin.`

## 2. Receding Signals

The environment may still inherit the one Living World, but the following must
recede into the background before commitment:

- language identity
- editor identity
- active tooling
- implementation-specific shell ownership
- project structure

Receding does not necessarily mean removing.

It means these signals may not compete with the identity of the place.

## 3. Place Legibility

The environment should feel like a meaningful place, not a temporary overlay.

It should communicate:

- welcome
- orientation
- calm
- possibility
- confidence

It should not communicate:

- setup friction
- software choice
- mode switching
- already-active authoring
- cognitive overload

The place should feel inhabited by purpose even before anything is created.

## 4. World Continuity

`Creative Initiation` still belongs to `Create World`.

That means the environment should preserve the law of one Living World:

- the creator should not feel they left Dropple
- the creator should not feel they opened another product
- the creator should not feel they were moved into a different editor family

At the same time, the environment must not behave like a language-owned
workspace before the creator has completed initiation.

This is the central tension the plan must preserve:

`same world`

without

`premature language ownership`

## 5. Transition Readiness

The environment should prepare for a lawful threshold into `Creative Arrival`.

That means it must make the departure condition legible:

`I know exactly how I want to begin.`

The environment should therefore support a transition that feels like:

- commitment
- threshold crossing
- the world responding

not:

- app launch
- editor unlock
- wizard completion
- screen replacement

## What Must Never Dominate This Place

The following must never become the primary identity of the environment:

- UIUX
- Graphic
- Animation
- Audio
- any specific creative language
- editor chrome
- template or blueprint browsing
- project setup
- implementation scaffolding

These may later become relevant in subsequent conversations, but they do not
own the place.

## Expression Questions

Future environment work should answer these questions:

1. What should dominate the creator's attention here?
2. What should recede into the background?
3. How should the place reveal that it is the beginning of creation?
4. How should it preserve continuity with the Living World?
5. How should it prepare the threshold into `Creative Arrival`?
6. What signals must never appear before commitment?

These are planning questions, not implementation instructions.

## Out of Scope

This document does not define:

- UI layout
- route ownership
- shell ownership
- canvas rendering behavior
- exact chrome visibility rules
- card copy
- button wording
- animation timing
- CI-1 refinement details

Those belong to later planning slices or implementation contracts.

## Success Condition

This environment plan is complete when future work can answer:

`How should Creative Initiation feel as a place?`

without reopening the identity of the place itself.

At that point, environment implementation planning may begin.
