# U28.1 First-Time User Orientation

Mission: determine whether a first-time user can understand Dropple as a persistent project world without explanation.

Core question:

Can someone who has never seen Dropple understand it, orient inside it, and choose a next step without learning the architecture?

## What U28.1 Is

- A real-user audit
- A product-understanding audit
- A mental-model audit

## What U28.1 Is Not

- Not an architecture audit
- Not an implementation phase
- Not a bug-fixing session
- Not a guided demo

## Session Rules

- No documentation
- No product explanation
- No architecture briefing
- No coaching during the task
- No feature teaching
- No corrections unless the user is completely blocked and the session must continue

If the user asks what to do, say:

> Do whatever feels most natural.

If the user asks what something means, say:

> Tell me what you think it means.

## Participant Profile

Use first-time users only.

Recommended sample:

- Minimum: 5
- Better: 7-10

## Environment Setup

- Clean browser session
- No persisted Dropple familiarity
- Screen recording if permitted
- Audio recording if permitted
- One moderator
- One note-taker if available

## Moderator Opening Script

Read exactly:

> Please open this product and think out loud as you use it. I'm not going to explain how it works. I want to understand what you think it is and how you would begin.

Do not explain:

- universe
- room
- perspective
- workflow
- Creative OS

## Test Structure

## 1. First 10 Seconds

Observe before the first click.

Record:

- First thing they looked at
- First thing they read
- First thing they ignored
- What they believed was the primary object on the screen

Why this matters:

- Dropple should make project, universe, and artifact feel primary
- Not buttons, tabs, menus, or chrome

## 2. First 60 Seconds

Ask:

- What do you think this product is?
- What do you think you can do here?
- Where would you start?

Record:

- Time to first click
- First click path
- Time to first coherent explanation
- Incorrect assumptions
- Visible hesitation
- Confusion points

Success target:

- Within 60 seconds, the user can explain:
  - what Dropple is
  - where they are
  - what they would do next

## 3. Hierarchy Check

Ask:

- What do you think owns everything else on this screen?

Good answers:

- the project
- the workspace
- the project universe
- the thing in the middle

Bad answers:

- I don't know
- the menu
- the app tab
- the toolbar

This tests whether the user understands screen hierarchy.

## 4. Silent Exploration Window

Let the user continue for 2-3 minutes with no help.

Watch:

- Where they go first
- Whether they stay project-first or tool-first
- Whether they treat room changes as project progress or tool switching
- Whether they appear lost in navigation or shell framing

Record:

- Hesitation
- Backtracking
- Dead ends
- Confusion language
- Whether they identify the project as the stable thing

## 5. Follow-Up Questions

Ask:

- What feels like the main thing on the screen?
- What do you think is the project?
- What do you think the other areas are?
- If you wanted to continue, what would you do next?

## 6. Persistent World Check

Ask:

- If you closed this page right now and came back tomorrow, what do you think would still exist?

Good answers:

- my project
- my work
- the universe
- the things I created

Weak answers:

- the UI
- the screen
- the editor

This tests whether the user perceives Dropple as a persistent world rather than a temporary tool surface.

## 7. Product Identity Prompt

Ask:

- If you had to describe Dropple to a friend in one sentence, what would you say it is?

Rule:

- Record the answer verbatim
- Do not categorize it during the session

## Evidence To Capture

For every participant, record:

- Participant ID
- Experience level
- Time to first click
- First click path
- Time to first coherent explanation
- Product guess
- Location guess
- Next-step guess
- What they thought owned the screen
- What they thought would persist tomorrow
- Wrong assumptions
- Confusion points
- Hesitation points
- Direct quotes

## Scoring

Score each participant on:

- Product Understanding: 0-2
- Location Understanding: 0-2
- Next-Step Clarity: 0-2
- Project-First Recognition: 0-2
- Persistent World Recognition: 0-2

Definitions:

### Product Understanding

- 0 = cannot explain what this is
- 1 = partial or vague explanation
- 2 = broadly correct explanation

### Location Understanding

- 0 = does not know where they are
- 1 = partial location understanding
- 2 = clearly understands current context

### Next-Step Clarity

- 0 = no plausible next action
- 1 = hesitant or weak next action
- 2 = confident plausible next action

### Project-First Recognition

- 0 = sees separate tools
- 1 = sees connected tools
- 2 = sees one project world

### Persistent World Recognition

- 0 = sees temporary tool state
- 1 = sees saved work but not clearly a persistent world
- 2 = sees a project world that persists beyond the current screen

Total score: 0-10

Interpretation:

- 9-10 = strong orientation
- 7-8 = mostly clear
- 5-6 = fragile
- below 5 = confusing

## Pass Criteria

U28.1 passes if most users:

- Understand what Dropple is within 60 seconds
- Understand where they are
- Choose a plausible next step
- Recognize the project as the owning object
- Perceive the experience as one project world
- Believe the project persists beyond the current screen

## Failure Signals

Flag as failure if users commonly:

- Describe it as just a design tool
- Cannot identify the main object on the screen
- Do not know where to begin
- Interpret perspective changes as switching apps
- See the interface as temporary rather than project-persistent
- Require explanation to form a coherent model

## Required Output

At the end of U28.1, produce:

1. Orientation success rate
2. Median time-to-understanding
3. Average Product Understanding score
4. Average Location Understanding score
5. Average Next-Step Clarity score
6. Average Project-First Recognition score
7. Average Persistent World Recognition score
8. Top five confusion points
9. Top five strongest quotes
10. Top five weakest quotes
11. Pass/fail verdict

## Decision Rule

- If Project-First Recognition and Persistent World Recognition are strong:
  - U29 should be polish-first
- If either is weak:
  - U29 should become clarity and orientation repair

## Why This Matters

This phase tests whether the Creative OS model exists in the user's mind, not just in the codebase.
