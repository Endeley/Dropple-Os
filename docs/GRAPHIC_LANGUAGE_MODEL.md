# Graphic Language Model

## Purpose

This document defines the Graphic creative language.

It does not define a new world.
It does not define a new shell.
It does not define a new activation subsystem.

Its purpose is to answer:

`How does Graphic think inside Create World?`

This document assumes the frozen architectural model:

- Create World owns the shared world substrate
- Create World Shell owns shared shell activation surfaces
- Product Expression owns how surfaces are presented
- Graphic owns the semantic language it projects into those surfaces

Graphic is therefore not a workspace-definition problem.
It is a creative-language-definition problem.

## 1. Creative Domain

Graphic belongs to the creative domain:

`Visual Communication`

This means the creator is not primarily arranging nodes.
The creator is composing visual meaning.

The product should therefore help the creator think in:

- composition
- hierarchy
- brand
- message
- emphasis
- visual relationships

before it teaches tools.

## 2. Creative World

Graphic's creative world is:

`Composition`

The creator is building a composition world.

That world may contain:

- a single artboard
- multiple artboards
- a poster
- a social graphic
- a brand board
- a presentation cover

But those are expressions inside the world.
They are not the world itself.

## 3. Core Language

The stable Graphic language is:

`Composition`

`-> Group`

`-> Object`

`-> Style`

`-> Effect`

This is the conceptual language.

Artifact types may expand over time.
The language should remain stable.

## 4. Identity

Graphic needs a primary artifact identity that gives the creator an immediate sense of what they are making first.

### Primary Artifact

`Artboard`

The artboard is the primary root artifact of Graphic.

It answers:

`Where does this composition live?`

### Identity Rule

Graphic creators should first understand:

- I am building a composition
- this composition begins on an artboard
- objects exist in service of the composition

They should not first think:

- frame
- rectangle
- node
- editor object

## 5. World Meaning

UIUX meaning is:

`Pages belong to Applications`

Graphic meaning should instead be:

`Artboards belong to Compositions`

and

`Compositions express Visual Communication`

This means:

- an artboard is not merely a surface
- it is a communication field
- objects are not merely elements
- they are contributors to composition, hierarchy, and message

## 6. Artifact Interpretation

Graphic should interpret its artifact family like this:

- `Artboard`
  - root composition surface
- `Group`
  - composition relationship holder
- `Shape`
  - visual form primitive
- `Vector`
  - precision graphic form
- `Text`
  - message, hierarchy, caption, title, wordmark
- `Image`
  - supporting asset, background, focal element, masked composition asset
- `Style`
  - color, typography, visual treatment
- `Effect`
  - depth, emphasis, atmosphere, motion-affecting treatment

The creator should understand not only what an artifact is, but what role it can play.

## 7. Starter Semantics

Graphic needs starter semantics that help a creator begin with intention instead of tools.

Recommended starter semantics:

- `Poster`
- `Social Graphic`
- `Brand Board`
- `Logo Sheet`
- `Flyer`
- `Presentation Cover`

These are not random templates.
They are meaningful starting directions inside the Graphic language.

### Starter Rule

Graphic starters should answer:

- what kind of communication artifact am I creating?
- what kind of composition is emerging?
- what is the likely next visual decision?

## 8. Momentum

Graphic momentum should describe the next meaningful thoughts a creator naturally has after the first artifact appears.

Recommended Graphic momentum sequence:

1. Establish Composition
2. Create Visual Hierarchy
3. Define Typography
4. Introduce Color System
5. Add Supporting Assets
6. Refine Style and Effects
7. Prepare for Export

This sequence should not be treated as a rigid workflow.
It is a semantic guidance path.

### Momentum Rule

Graphic guidance should help the creator ask:

- what is the focal point?
- what carries the message?
- what needs stronger hierarchy?
- what visual system should unify this composition?

before it asks for low-level property editing.

## 9. Evolution

Graphic needs an evolution path the product can reveal over time.

Recommended evolution shape:

`Artboard`

`-> Composition`

`-> Communication Piece`

`-> Campaign Asset`

`-> Brand System`

This path may vary by context, but it gives Graphic a meaningful progression beyond isolated objects.

### Example Evolution Paths

- `Shape -> Icon -> Badge -> Illustration Element`
- `Text -> Title -> Wordmark -> Caption`
- `Image -> Poster Image -> Background -> Masked Asset`
- `Group -> Layout Group -> Brand Lockup -> Reusable Visual Component`

The product should reveal what something can become, not merely what tool created it.

## 10. Capability Framing

Graphic should frame its capability domains like this:

- Structure
- Arrangement
- Typography
- Color
- Effects
- Motion
- Export

These are Graphic language concerns.
They should become prominent by context.

For example:

- empty world:
  starter choice and import become prominent
- artboard created:
  composition and hierarchy become prominent
- object selected:
  style and arrangement become prominent
- multiple objects selected:
  grouping and composition structure become prominent
- motion attached:
  timeline becomes relevant

## 11. Projection Rules

Graphic projection should follow the same creator-first laws already established elsewhere in Dropple.

### Empty World

The creator should understand:

- I am creating a visual composition
- everything begins with an artboard or imported asset
- I can start from a meaningful communication direction

### First Artboard

The creator should understand:

- this artboard belongs to a composition
- now establish hierarchy and message

### Object Selection

The creator should understand:

- what this object contributes to the composition
- how it participates in style, hierarchy, or emphasis

### Multiple Selection

The creator should understand:

- this is now a composition structure problem
- grouping and arrangement are relevant

## 12. Inheritance Assumption

Graphic inherits:

- Create World
- Create World Navigation
- Create World Activation
- Product Expression patterns

Graphic provides:

- Graphic vocabulary
- Graphic starter semantics
- Graphic projection content
- Graphic momentum
- Graphic evolution
- Graphic-specific tools
- Graphic-specific panels

That is the correct constitutional posture for Graphic.

## 13. Non-Goals

This document does not:

- define shell extraction
- define route changes
- define runtime changes
- define compiler changes
- define UI implementation details

It defines language only.

## 14. Conclusion

Graphic thinks in:

`Composition`

not:

`canvas objects`

It begins with:

`Artboard`

not:

`frame-like geometry`

It progresses through:

- hierarchy
- typography
- color
- assets
- effects
- export

not through generic editor operations.

This is the first Graphic language boundary for Dropple's multi-language era.
