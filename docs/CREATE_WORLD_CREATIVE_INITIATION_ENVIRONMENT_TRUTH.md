# Create World Creative Initiation Environment Truth

## Purpose

This document freezes the product truth for the environment in which
`Creative Initiation` happens.

It exists because creator review uncovered a missing truth:

- the conversation of `Creative Initiation` is defined
- the place in which that conversation happens is not yet defined

This document does not decide:

- route structure
- shell composition
- canvas implementation
- chrome timing
- animation behavior

Those belong to later planning and implementation work.

This document answers a more fundamental question:

`What is the identity of the place before creation begins?`

## Foundational Finding

Creator review uncovered a chapter-boundary leak.

The current prototype hosts a pre-language conversation inside a post-language
environment.

That means the creator is receiving signals from different chapters at once:

- `Creative Initiation` asks about intention
- `UIUX` shell signals that a language is already chosen
- `Create World` substrate signals that the creator is already inside authoring

The discomfort in the current experience is therefore not merely a UI issue.

It is a missing place truth.

## Place Truth

Every place in `Create World` must have an immediately understandable identity.

For `Creative Initiation`, that identity is:

`Creative Initiation is the place where intention becomes direction before creation begins.`

This is the truth future environment planning must preserve.

## 1. Identity

`Creative Initiation` is not:

- a launcher
- a template gallery
- a blueprint gallery
- a setup wizard
- an editor
- a language workspace

It is the threshold where a creator clarifies what they are trying to bring
into existence before creation becomes concrete.

Its identity should be immediately understandable as:

- a place for beginning
- a place for deciding direction
- a place for gaining confidence

The creator should not have to infer whether they are:

- already editing
- choosing software
- configuring a project
- browsing implementation options

## 2. Purpose

The purpose of `Creative Initiation` is to help the creator move from:

`I have an idea.`

to:

`I know how I want to begin.`

It exists to transform vague intention into usable direction.

It does not exist to:

- expose tooling
- teach interface mechanics
- present project management
- ask for technical configuration
- collapse directly into authoring

Its purpose is clarity before commitment.

## 3. Arrival

When the creator arrives here, they should immediately understand:

- I am not inside a generic editor
- I am not being asked to choose software
- I am in the beginning place of creation
- this place exists to help me decide how to begin

The first felt question should be:

`What am I trying to create?`

not:

- `Which workspace is this?`
- `What can I click?`
- `Why is the editor already open?`
- `Am I supposed to start drawing now?`

Arrival succeeds when the creator feels oriented in meaning before they are
oriented in tools.

## 4. Boundary

The following do not belong in `Creative Initiation` as dominant signals:

- language-owned shell identity
- editor chrome as the primary subject
- project-management concepts
- file-management concepts
- technical setup
- runtime vocabulary
- tooling that competes with the opening conversation
- environment signals that imply creation has already begun

This does not mean the shared world must disappear.

It means the environment may not present itself primarily as:

- a UIUX workspace
- a Graphic workspace
- an Animation workspace
- an already-active editor

Before commitment, the environment must belong to `Create World`, not to any
creative language.

## 5. Departure

The creator is ready to leave `Creative Initiation` when they can honestly say:

`I know exactly how I want to begin.`

That is the departure condition for the place.

At that point:

- `Creative Initiation` has done its job
- commitment may occur
- `Creative Arrival` may begin

Departure should feel like crossing a threshold, not like opening another app.

The creator should feel:

- ready
- understood
- committed

not:

- interrupted
- transferred
- re-onboarded

## Consequence for Future Planning

Any future environment plan for `Creative Initiation` must preserve these
truths:

1. `Creative Initiation` belongs to `Create World`, not to any creative
   language.
2. The creator must understand the identity of the place immediately.
3. The place exists to clarify intention into direction before creation begins.
4. Dominant editor or language signals cannot outrank the opening purpose of
   the place.
5. Departure must hand the creator into `Creative Arrival` as one continuous
   world transition.

## Conclusion

The unresolved problem in the current prototype is not merely card wording,
chrome timing, or route naming.

It is that the place before creation begins does not yet have a frozen
identity.

This document defines that identity:

`Creative Initiation is the place where intention becomes direction before creation begins.`

That truth should now govern the next environment-planning step.
