## Purpose

Define the smallest implementation blueprint required to build the
`Origin Region` as a real place in the `First World`.

This document does not redefine `Projection`, `Revelation`, or the
`Dropple World Pipeline`.

It translates the already-frozen constitutional work into a bounded
engineering slice that can be built directly.

## Implementation Objective

Build the `Origin Region` as the Traveler's real entry place in the
`First World`.

The `Origin Region` is not a homepage, dashboard, or privileged presentation
surface.

It is:

- the Traveler's default spawn location
- the canonical entry into the world
- the navigation fallback region
- the stable starting reference for projection

The current implementation label `home` remains temporary and may persist as
an internal identifier during this slice.

It is not a protected world name.

## 1. Origin Entities

Only the following entities belong in `Slice 1`.

### Protected Entities

#### 1. Origin Region

The region-level world entity currently addressed by the temporary internal
id `home`.

Responsibilities in this slice:

- exist as the world's starting region
- anchor the Traveler's first placement
- provide the first stable world relationship
- remain one region among many rather than a privileged page

#### 2. Origin Path

The central path already visible in the world.

Responsibilities in this slice:

- serve as an intentional world element
- communicate directional continuity through the `Origin Region`
- visually connect the Traveler's entry point to the rest of the world

#### 3. Horizon Atmosphere

The horizon and atmospheric depth layer already visible in the world.

Responsibilities in this slice:

- establish scale and depth
- communicate that the world extends beyond the immediate origin place
- remain environmental rather than interactive

#### 4. Distant Regions

The existing visible regions beyond the `Origin Region`:

- `build`
- `media`
- `design`
- `system`
- `collaborate`

Responsibilities in this slice:

- remain present as real world destinations
- preserve world continuity beyond origin
- support orientation rather than immediate complexity

### Excluded Entities

The following are not introduced in `Slice 1`:

- traveler-owned tools
- living objects
- interactive props beyond region travel
- additional landmarks not required for origin implementation
- education or translation region surfaces

## 2. Traveler Spawn

### Initial Position

The Traveler spawns at the current world origin already defined by the
temporary `home` region coordinates.

For `Slice 1`, the existing stable starting coordinates remain authoritative:

- `x: 0`
- `y: 140`
- `z: 0`

### Initial Orientation

The Traveler begins oriented into the `Origin Region` with the world opening
outward toward the visible distant regions.

This slice does not add free look, alternate spawn headings, or cinematic
arrival choreography.

### Initial State

On first load, the Traveler is:

- present in the `Origin Region`
- not yet traveling
- not yet interacting with additional world systems
- positioned for orientation rather than immediate action overload

### Relationship to the Origin Region

The Traveler's first lawful world relationship is:

`Traveler is at Origin Region`

This relationship must be true before later slices add richer revelation or
interaction behavior.

## 3. Immediate Visibility

The following must be visible immediately on arrival.

### Environmental Visibility

- origin path
- horizon atmosphere
- mountain ranges
- river basin
- stable environmental depth cues

### World Visibility

- the `Origin Region` as the current starting place
- distant regions as real places in the same world
- navigation rail as interaction authority, not as world representation

### What Immediate Visibility Must Avoid

- large explanatory overlays
- hero-like composition
- card-era landmark presentation
- unrelated decorative entities with no world identity

## 4. Discoverable Elements

`Slice 1` introduces only minimal discovery.

The purpose is orientation, not deep revelation.

### Discoverable in this Slice

- that the world continues beyond the origin place
- that the distant visible regions are reachable destinations
- that the origin place is a real region rather than a page

### Not Yet Discoverable in this Slice

- richer landmark identity
- traveler memory systems
- layered revelation chains
- region-specific narrative knowledge
- multi-step discovery sequences

Those belong to later slices.

## 5. Allowed Interactions

Only interactions that are already necessary for truthful origin behavior
belong in this slice.

### Included

#### 1. Region Travel Request

The Traveler may request travel from the `Origin Region` to one of the
existing visible regions through the existing navigation authority.

This preserves the constitutional separation:

- `NavigationFramework` remains interaction authority
- `Projection` remains pure

#### 2. Scroll-Based Travel Through the Existing World Path

If the current First World already supports bounded scroll-driven travel,
that behavior may remain only insofar as it expresses legitimate world
movement and not legacy presentation semantics.

### Excluded

- click-to-reveal systems
- contextual tool surfaces
- world inspection panels
- entity explanation overlays
- traveler progression interactions
- new revelation mechanics beyond what a later bounded slice will add

## 6. Explicit Non-Goals

`Slice 1` must not attempt to do the work of later slices.

### This Slice Does Not Introduce

- traveler progression systems
- first revelation implementation
- region renaming from `home` to a final world identity
- additional region construction
- living object systems
- landmark orchestration beyond origin essentials
- advanced arrival presentation
- new architecture or constitutional documents
- visual polish work unrelated to origin truth

### This Slice Does Not Redefine

- `ARR2.0`
- `ARR2.1`
- `Origin Region` protected role
- `home` as a temporary implementation label

## Implementation Boundaries

### Preserve

- current world region registry shape unless origin implementation truly
  requires a bounded change
- current origin semantics
- existing navigation authority
- existing projection purity
- existing first-world constitutional test surface

### Avoid

- spreading new dependencies on the label `Home`
- treating the origin as a homepage
- adding placeholder visuals to make the scene feel less empty
- introducing entities without clear world purpose

## Success Criteria

`ORIGIN_REGION_IMPLEMENTATION.md` is complete when an engineer can begin
building `Slice 1` without asking new architectural questions.

`Slice 1` itself should be considered complete only when:

- the `Origin Region` exists as a real place rather than an application
  concept
- the Traveler has a stable and truthful starting relationship to it
- immediate world visibility supports orientation
- distant regions remain present as real destinations
- no new legacy presentation assumptions are introduced

## Implementation Sequence

Build `Slice 1` in this order:

1. Preserve current origin semantics while treating `home` only as a
   temporary internal label.
2. Make the `Origin Region` explicit as a place in implementation.
3. Confirm Traveler spawn and initial relationship to origin.
4. Validate immediate visibility and destination continuity.
5. Re-run focused First World validation before moving to the Traveler slice.

## Standing Review Question

At the end of `Slice 1`, the implementation must answer:

`What makes this place the Origin Region?`

If the answer depends on homepage conventions, the slice has drifted.

If the answer depends on world role, traveler entry, and place identity, the
slice is on track.
