# Workspace Mode Policy (Executive)

## Purpose

Dropple scales through a small number of core workspaces, many modes, and shared platform systems.

We do not add new workspaces for every new feature.

We expand by:
- deepening existing modes
- adding new modes inside existing workspaces
- extending shared systems

## Core Rule

Workspace = why the user is here  
Mode = what they are doing  
Tools = how they do it  
System = what powers everything

## The 5 Core Workspaces

### Design
For visual product creation.

Primary active mode:
- UI / UX Design

Secondary modes:
- Graphic Design
- Branding
- Icon Design
- Document / Print
- Light Design System Authoring

### Media
For time-based creation.

Primary active mode:
- Animation / Cartoon

Secondary modes:
- Motion Design
- Video Editing
- Podcast / Audio

### Build
For application and system creation.

Modes:
- Application Builder
- Data & Logic
- State Machines
- API / Integration
- AI-assisted Building

### System
For reusable systems and governance.

Stable core modes:
- Design Tokens
- Theming
- Versioning

Expansion modes:
- Component Libraries
- Variants

### Collaborate
For coordination and review.

Modes:
- Review
- Comments
- Project Management
- Production
- Knowledge

## Product Quality Rule

No mode should be treated as product-ready unless it has:
- canonical taxonomy
- capability exposure
- deterministic truth
- projection before UI logic
- one closed primary workflow
- end-to-end coverage
- no duplicate legacy authority path

## Strategic Rule

Dropple is not a collection of disconnected tools.

Dropple is a unified creation system with:
- motion as a first-class platform capability
- reusable systems
- deterministic runtime behavior
- workspace-specific entry points
