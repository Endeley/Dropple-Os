# W1.3 Substrate Identity

## Purpose

This document freezes the first substrate-identity decisions for WorldShell after shell reduction.

W1.1 and W1.2 proved:

- the substrate owns the viewport
- orientation can be reduced to a Project Capsule
- operations can exist as floating controls
- permanent shell support surfaces can be removed

W1.3 does not continue shell cleanup.

W1.3 defines what the world is.

## Core Rule

The answer to an empty world is not more UI.

The answer is world identity.

## Decision 1 — Project Home

Three spatial concepts are now distinct:

- `Project Origin`
  - The immutable coordinate anchor of the project world.
  - It does not move when the user pans or zooms.
  - It is the substrate-level reference point.

- `Project Home`
  - The preferred camera target for returning to the project.
  - Reset/Fit/Home behaviors resolve here by default.
  - Home is stable, but may evolve as the project gains structure.

- `Current Focus`
  - The active working area the user is currently engaged with.
  - Focus changes frequently.
  - Focus is not the same thing as origin or home.

### W1.3 Freeze

For `Create > UI`:

- `Project Origin` exists at the world coordinate anchor
- `Project Home` is the default Create working region
- `Current Focus` is the currently active artifact or selection region

Camera behavior must preserve this distinction.

## Decision 2 — First Artifact

For `Create > UI`, the first meaningful world artifact is:

- `Frame`

### Reason

`UI Project -> Screen -> Frame -> Elements`

The world needs a first structural object that gives creation a clear starting point.

A `Frame` establishes:

- screen-scale intention
- placement in the project world
- a container for subsequent elements

### W1.3 Freeze

The substrate should treat `Frame` as the first-create artifact for `Create > UI`.

World behavior should assume creation begins by placing or focusing a frame-like surface, not by opening another editor shell.

## Decision 3 — Empty World Behavior

A brand-new project must not be interpreted as "nothing exists."

It must be interpreted as:

- a persistent project world
- ready for creation
- centered on an intentional working region

### W1.3 Freeze

Empty-world behavior for `Create > UI`:

- no onboarding dashboard
- no tutorial cards
- no summary panel
- no permanent assistant panel
- no workspace shell recovery surfaces

Instead:

- Project Home exists
- the world opens in a ready state
- the first-create action is structurally clear
- the substrate remains mostly empty, but intentional

Empty is allowed.

Meaningless empty is not.

## Decision 4 — Scale Semantics

Scale must describe project context, not just pixel size.

### Freeze

- `Zoom In = more artifact detail`
- `Zoom Out = more project context`

This is a semantic rule, not just a camera rule.

It is the seed of future world continuity:

- Artifact
- Region
- Project
- Universe

W1.3 does not implement the full universe continuum.

W1.3 only freezes what zoom means.

## Behavioral Implications

After this document:

- camera behavior must distinguish origin, home, and focus
- creation behavior should assume `Frame` as the first artifact in `Create > UI`
- empty-world behavior should preserve openness without falling back into shell surfaces
- zoom behavior should be designed around contextual meaning, not visual scaling alone

## Out Of Scope

This document does not define:

- final world visuals
- motion system details
- full universe zoom continuum
- tool rail redesign
- assistant redesign
- onboarding flows

Those decisions come later.

## W1.3 Success Condition

The world should begin to feel like:

- a place with a home
- a place where creation begins intentionally
- a place whose emptiness has meaning
- a place where scale reveals context

Not:

- a blank viewport waiting for more UI
